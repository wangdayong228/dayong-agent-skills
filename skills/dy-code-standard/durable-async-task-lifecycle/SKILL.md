# 持久化异步任务生命周期

适用于保存执行进度、调用外部系统完成付款、转账、发货或上传的后台任务。**没收到结果，不等于操作失败；本地停止任务，不等于外部操作已经停止。**

## 先确定项目规则

沿用已确认的规则，明确各状态的含义、允许动作、进入条件及哪些状态不可逆。重试次数、间隔、截止时间、取消权限和人工处理条件由项目决定，仅确认未决项；不默认无限重试。

## 超时、重启与重试

首次发送前保存任务标识、原参数和幂等键。超时、重启或数据库提交结果未知时，按已有记录查原操作，不能换 key 或新建任务绕过未决请求。

区分查询原操作、用原 key 重发、发起新业务操作。重发前核对上游去重范围、有效期和参数要求；相同 key 不保证永久去重。例如付款超时后查无记录，可能只是数据尚未同步，不能直接当成未付款。

| 已知情况 | 处理 |
| --- | --- |
| 超时、断连、暂时查不到结果 | 继续安全查询；无法自动查明时按项目规则暂停或交人工处理 |
| 原操作确定失败 | 按上游明确的错误分类、接口约定及业务规则判断能否重试，不凭错误文案猜测 |
| 次数或时间用完 | 可以停止自动尝试；即使任务进入终态，也须安排未决请求的后续核对 |

## 收到取消申请时

先保存取消申请，阻止后续不允许的发送；申请取消不等于取消完成。

- **尚未发送**：确认其他 worker 也不会再发送，才能完成取消。
- **已发送、结果未知**：继续查原操作；上游支持撤销时，核实撤销是否完成。
- **已经成功**：保留成功事实，是否退款或撤销由业务规则决定；后续操作单独记录，不能把原操作改成“没发生”。

取消完成须有证据证明原操作没发生、以后也不会发生。管理员意愿、超时或一次查无记录均不足以证明。

## 允许同一资源接受新任务前

项目若限制同一资源不能同时执行冲突任务，这个限制称为“占位”。释放占位前，须查清并处理已发送请求，确认旧 worker 不会再发送冲突请求。

锁或租约过期不代表旧 worker 停止；修改数据库也拦不住已通过检查、准备发送的旧 worker。必须确认这些旧请求不会再干扰新任务。

状态更新、占位释放和新任务受理须有事务或等效一致性保证。用条件更新、版本号等防止取消、回调、恢复互相覆盖；这些措施不能代替对旧 worker 发送行为的控制。

## 整批暂停或任务结束后

整批暂停、失败或取消时，已提交子任务仍须跟踪并保存结果。例如 B 失败导致整批暂停，已提交的 C 不能无人处理。明确整批结束条件；允许先结束时，明确由谁继续核对、处理已发生的操作。

项目声明不可逆的结束状态称为“终态”，不能因重试、人工恢复或迟到通知而改写。再次操作须创建关联的新任务，保留旧记录，并先满足原请求已查清、占位可释放等条件。迟到结果与终态矛盾时保留证据并排查，不能忽略或直接重做。

## 验证与边界

覆盖响应丢失、外部成功但本地保存失败、重启、取消与发送竞争、重复或迟到通知、整批暂停后子任务收尾。确认不重复执行、不提前释放占位、不改写不可逆终态；报告标明测试直接设置的状态，不能冒充真实故障触发。

普通定时清理、纯计算和仅返回错误的单次请求不套用整套流程。本 skill 不选择队列、调度或日志告警方案。

`fail-fast-with-evidence` 管错误输出，`continue-on-connection-loss` 管断连后进程继续运行，本 skill 管任务推进。当前操作失败立即停止，下一轮恢复另按对应规则判断。
