# 用户界面与交互

仅约束 Web、App、桌面程序及 CLI 中面向用户的界面、文案和操作流程；混合任务只约束相关部分。不涉及用户交互的内部逻辑、机器间接口、自动化脚本及一般文档改动不适用。

以易理解、易操作为首要目标：用户仅凭界面或终端输出，就能理解当前状态、可执行操作、操作结果与下一步，并完成当前流程。

## 技能分工

按场景**必须调用**下列技能，无需用户点名；仅采用目标平台适用的指导。图形界面指 Web、App、桌面程序，CLI 不触发图形界面专用技能。

| 适用界面 | 场景与职责 | 技能 | 排除（不触发） |
|----------|------------|------|--------------|
| 图形界面 | 设计/修改结构、流程、响应式、无障碍及文案展示时机 | `ui-ux-pro-max` | 不影响布局与交互的文案修正 |
| 图形界面 | 新建界面、视觉/排版/层级调整及文案打磨；落实已确认规范与术语 | `frontend-design` | 不改变含义的错字修正 |
| 图形界面 | 微交互、加载、反馈、过渡与恢复引导；协调文案、控件和状态 | `interaction-design` | 无交互或反馈变化 |
| 全部（含 CLI） | 编写/修改/审查错误提示，确保原因具体有据 | `fail-fast-with-evidence` | 未触及错误提示；既有提示已具体有据时不为统一形式改写 |
| Web | UI 改动完成或体验审查：检查受影响的表单、焦点、键盘、文案与反馈 | `web-design-guidelines` | 不影响含义/布局/交互的错字修正 |
| Web | 可运行时验证页面效果、关键操作与恢复路径 | `ego-browser` | |

## 文案与操作引导

- 用用户熟悉的语言，保持术语一致；按钮、命令与选项明确动作及对象，如“保存设置”。
- 提示明确对象、状态或失败条件。错误以本次事实为依据，先说明已确认的最具体原因（含底层原因），保留操作、环节与必要证据，用用户语言表达，禁止笼统包装；原因未明只述已知事实，不猜测或混列互斥原因。敏感信息按 `fail-fast-with-evidence` 排除。
- 用户可解决的问题必须提供与原因匹配的入口或引导，说明在哪里、做什么、如何继续：图形界面有直接修复动作就提供按钮；CLI 给出可执行命令示例、参数说明或交互式选择与提示；执行后及时反馈进度与结果。
- 保留已输入的字段、参数和必要上下文，修复后继续原流程；再次提交或执行由用户明确触发，不要求从头开始。
- 重试遵守实际恢复条件及既有约束；用户无法自行解决时说明阻塞原因、当前状态和实际可用的下一步，不提供无效操作或循环引导。

例如：提示“验证码已过期，无法登录”并提供“重新获取验证码”按钮；CLI 缺少必填参数时指出参数名、用法并给出补全示例。

图形界面优先沿用已有设计系统，CLI 沿用命令与参数约定；局部改动只做相关阶段与专项检查，无需重建设计系统。验证受影响的正常完成、可恢复失败及恢复后继续操作的路径：Web 用浏览器，App/桌面用平台工具，CLI 用终端；无法运行须说明未验证路径与原因。
